```
                             │              │              │
                   ┌─────────▼───┐  ┌───────▼─────┐  ┌─────▼──────┐
                   │ windows.py  │  │   diff.py   │  │  audit.py  │   ← 四个子命令层
                   └─────┬───────┘  └──────┬──────┘  └─────┬──────┘
                         │                 │               │
                         └────────┬────────┴───────┬───────┘
                                  │                │
                          ┌───────▼──────┐  ┌──────▼───────┐
                          │ timeline.py  │  │  report.py   │  ← 语义层 / 呈现层
                          └───┬──────┬───┘  └──────┬───────┘
                              │      │             │
                    ┌─────────▼──┐ ┌─▼──────────┐  │
                    │ tzif.py    │ │ posix_tz.py│  │   ← 解析层（纯函数，无 IO）
                    └─────────┬──┘ └─────┬──────┘  │
                              │          │         │
                    ┌─────────▼──────────▼─────────▼──────┐
                    │ zoneinfo_store.py（树扫描 / 版本标签） │  ← 数据访问层
                    └─────────────────┬───────────────────┘
                                      │
                              ┌───────▼────────┐
                              │ errors.py      │  ← 退出码与异常类型（单点）
                              └────────────────┘
```

**依赖方向是单向的**：上层可以 import 下层，下层**禁止** import 上层（`report` 不得 import `windows`，
`tzif` 不得 import `timeline`）。这条由 `tests/test_architecture.py` 的 AST 扫描守门
（不是靠人记），理由：反向依赖会让"双引擎"退化成"引擎互相补丁"，也让 M1 的独立参照实现对拍失去意义。

| 模块 | 职责 | 允许的依赖 | 确定性要求 |
|---|---|---|---|
| `errors.py` | 退出码常量、`TzAuditError` 家族 | 无 | — |
| `tzif.py` | TZif v1–v4 字节解析 → `TzifData` | errors | 纯函数：字节进、结构出 |
| `posix_tz.py` | POSIX TZ 串解析与规则展开 | errors | 纯函数 |
| `zoneinfo_store.py` | 目录扫描、zone→路径、版本标签、link 识别 | errors | 只读文件；排序按字节序 |
| `timeline.py` | 表 + tail 合并、`resolve_local` / `to_local` / `roundtrip` | tzif, posix_tz, zoneinfo_store | 不读时钟、不读 `TZ` |
| `windows.py` | 年度 gap/overlap 扫描（双判据） | timeline | 排序固定 |
| `diff.py` | 两树对齐、四类互斥分类 | timeline, zoneinfo_store | 排序固定、判定顺序固定 |
| `audit.py` | 本地时刻清单判定 | timeline, diff | 保持输入行序 |
| `report.py` | Markdown / JSON 双轨、报告头、`--fail-on` | errors | 除 `generated_at` 外零时间戳 |
| `cli.py` | 参数、退出码映射、stdout/stderr 分工 | 全部 | 退出码只看结果集 |

## 二、关键设计决策

### 2.1 统一中间表示：`Timeline`

`Timeline` 是"某 zone 在某棵树下的一条有序映射"，字段固定：

```text
Timeline(
  zone: str,
  version: str,                 # 来自 provenance.json / 目录名，见 2.4
  segments: [Segment],          # 升序，按 utc_start 排列
  tail: PosixTz | None,         # 表外规则；无则 None（表示"表到无穷"）
  table_end_utc: int | None,    # 显式表最后一个转换点
)
Segment(utc_start, utc_end, offset_sec, abbr, is_dst, source)  # source ∈ {table, tail}
```

- **所有时刻内部一律用 UTC epoch 秒（整数）**，不用 `datetime` 做算术——避免平台 `datetime`
  行为差异，也让"双跑逐字节一致"没有浮点/时区对象参与。
- 输出层才转成 `YYYY-MM-DD HH:MM:SS`（本地墙钟串，无偏移后缀，偏移单独字段）。
- `source` 是**一等字段**：M3 的 `evidence=tail` 与 M2 的窗口来源都靠它，不能事后推断。

### 2.2 双引擎合并规则（唯一实现点）

1. 读 TZif → 显式转换点表；读 footer → `PosixTz`。
2. `table_end_utc` = 表内最后一个转换点；表覆盖 `[first, last)`。
3. 表外（`utc >= table_end_utc`）用 tail 展开，`source="tail"`；若 tail 为空（`TZif` 无 footer），
   表外沿用最后一个 offset，`source="table"` 并记 `open_ended=true`。
4. **slim 构建的常见形态**：表只到 1970 附近或为空、规则全在 tail → 该 zone 的 `table_end_utc`
   可能很早，tail 覆盖绝大部分历史。因此 tail 展开**必须支持负数年份起点**（从 `--window` 起点或
   表尾回推），不得只从"现在"往后展开。
5. 冲突判定：显式转换点优先；tail 只在其后生效。**不做事后"修正"**。

> 这条对应题目 §1.5 的 580/598 结论：只读表会得到"没有变化"的假结论。合并逻辑必须让
> `PST8PDT,M3.2.0,M11.1.0 → MST7` 这种"表内零迁移"的差异在 `timeline` 层就可见（tail 字段不同）。

### 2.3 本地→UTC 反解（M2 地基）

```python
resolve_local(local_naive, timeline) -> list[Resolution]   # 0/1/2 个
Resolution(utc, offset_sec, abbr, is_dst, fold)
to_local(utc, timeline) -> LocalNaive
roundtrip(local, timeline) -> list[LocalNaive]
```

- 存在性**只由结果个数决定**（0=GAP / 1=OK / 2=OVERLAP），与 `fold` 取值无关；
  `fold` 只用于在 2 个候选里**选择**（PEP 495）。
- `data/README.md` §4.1 的双判据是**判定层**的写法（面向"给定 fold 的 offset 比较"），
  实现层等价于"候选个数 + 候选是否自洽"；两者必须由 `tests/test_windows.py` 交叉断言一致，
  防止实现层偷偷只留一条判据。

### 2.4 版本标签与 provenance

每棵树的根目录可带 `provenance.json`：

```json
{"version": "2026a", "source_url": "...", "sha256": "...", "kind": "source|slim|fat", "retrieved": "YYYY-MM-DD"}
```

- 版本标签解析顺序：`provenance.json.version` → 目录名匹配 `^\d{4}[a-z]$` 或 `^\d{4}\.\d+$` → `unknown`。
- `report` 要求两棵树的标签都**不是 `unknown`**，否则退出码 3（环境不满足），不猜。
- `kind` 用于 M3 的 slim/fat 说明与 `data/README` 的对账；缺失时输出 `kind: unknown`，不推断。

### 2.5 确定性（贯穿全链，逐条可断言）

| 项 | 规则 | 守门 |
|---|---|---|
| 时钟 | 只有 `report.generated_at` 读时钟；测试用 `SOURCE_DATE_EPOCH` 冻结 | 双跑逐字节 |
| `TZ` / `locale` | 进程内**从不**读取；`time.tzset` 不调用 | AST 扫描 `os.environ["TZ"]`、`time.tzset` |
| 排序 | 一律 `key=lambda s: s.encode("utf-8")`；不依赖 `set`/`dict` 迭代序 | 双跑 + 显式排序断言 |
| 浮点 | 无；全部整数秒 / 整数分钟 | AST 扫描 `float(`、`round(` |
| 路径 | 输出**不含**绝对路径、主机名、用户名 | 报告快照断言 |
| JSON | `json.dumps(..., ensure_ascii=False, sort_keys=True, indent=2)` + LF + 尾换行 | `serialize.py` 单点写盘 |

**写盘单点**：所有 JSON / Markdown 落盘走 `serialize.py::write_text_atomic`（临时文件 + `os.replace`），
避免"两个子命令一个带 BOM 一个不带"。stdout 输出走同一序列化函数，保证"文件 == 管道"。

### 2.6 退出码（单点定义在 `data/README.md` §4.4）

`errors.py` 只做**常量映射**，不另立语义。骨架期新增的 `5 = 功能未就绪` 已在 `data/README.md`
§4.4 登记，并带**退役流程**（删常量 → 改 CLI → 改测试 → 改文档 → 决策记录），
每个模块落地时逐条退役；`tests/test_exit_codes.py` 里有 `not hasattr(errors, "EXIT_NOT_READY")`
一类的防复活断言（M2 起逐项加）。

## 三、技术选型

| 选项 | 结论 | 理由 |
|---|---|---|
| 语言 | **Python ≥ 3.8**（本机 3.8.8 / 3.12 双通道） | 题面要求 `pyproject.toml` + `[project.scripts]`；`zoneinfo` 不必用（自研解析是产品本体） |
| 运行时依赖 | **零**（仅标准库） | 审计工具的可信度建立在"你看到的就是全部"；也避免 `tzdata` 包反向污染被测数据 |
| 构建 | `setuptools` + `pyproject.toml`（src 布局） | 3.8 兼容最好；`pip install -e .` 即可用 |
| 测试 | `pytest`（dev extra） | 与 CI 矩阵一致；不用 `tox`（矩阵在 CI 里） |
| CLI 框架 | `argparse` | 零依赖；退出码 2 语义天然符合"用法错误" |
| JSON | `json`（标准库） | 键序固定靠 `sort_keys=True`，不引第三方 |
| 时间 | **自研 civil↔epoch 换算**（`civil.py`） | `datetime` 的 `fold`/平台行为不可控；自研实现可用 `datetime` 做**交叉证伪**（测试里） |
| 报告 | 自写 Markdown 渲染 | 表格列序固定、零外链、可逐字节比对 |

### 3.1 为什么自研 civil 换算（而不是全用 `datetime`）

- 题目要求"同一输入双跑逐字节一致"且要能对拍独立参照实现。若内部全用 `datetime`，
  对拍就变成"用同一个库验自己"。
- `datetime` 在 3.8/3.12 的 `fold` 行为一致，但 `astimezone` 依赖系统 zoneinfo（与"不读系统时区"纪律冲突）。
- 自研实现（days_from_civil / civil_from_days，Howard Hinnant 算法）只有整数运算，可用标准库
  **全量交叉证伪**（`tests/test_civil.py`：fixture 每一行 + 闰年/月末/负年份扫描），
  与 skill"时间轴手写算术要用 stdlib 全量交叉证伪"一致。

### 3.2 弃选（与 `plan/00` 决策记录一致，此处只记技术侧）

| 弃选 | 技术理由 |
|---|---|
| `zoneinfo` / `pytz` / `dateutil` | 它们读系统或包内数据，无法"指定两棵树"；且 `zoneinfo` 对不存在的本地时刻静默返回假 offset（题面实测） |
| `tzdata` PyPI 包作为运行时依赖 | 会把"被测数据"变成"工具依赖"，版本漂移不可控 |
| pandas / numpy | 数据规模是 598 zone × 数十万秒，纯 Python 足够；引入依赖破坏零依赖承诺 |
| `click` / `typer` | 多一层依赖，且退出码/`SystemExit` 语义需要额外适配 |
| Web / GUI / exe | 题面 §六 明确非目标；Markdown + JSON 供 CI 消费 |
| 联网校验最新版本 | 违反"运行时零网络"红线（题面 §1.8） |

## 五、构建与本地验证

```bash
# 本机（Windows + Git Bash；py 启动器）
py -3.12 -m pip install -e ".[dev]"
py -3.12 -m pytest -q
py -3.12 -m tzaudit --help
py -3.12 tools/check-sprint-layout.py
py -3.12 tools/check-desensitized.py
```

- **两个解释器通道都要跑**：`py -3.8` 是底线（语法必须兼容），`py -3.12` 是日常。
  CI 矩阵固定 `3.8 × {ubuntu, windows}` 与 `3.12 × {ubuntu, windows}` 四格。
- **不写 `python`**（本机是商店占位符），一律 `py -X utf8`（中文控制台编码）。
- `pip` 若被注册表代理污染：`NO_PROXY="*" no_proxy="*" py -m pip install -i <镜像> <pkg>`。

## 六、构建期不变量（构建门要断言的）

1. `src/tzaudit/__init__.py` 的 `__version__` == `pyproject.toml` 的 `project.version` == README 顶部标签
   （三处一致，`tests/test_version.py` 断言）。

4. `data/tzdb/*/` 与 `data/fixtures/*/` 的 `expect.json` 只含**输入与期望**，不含 `observed_*` 字段
   （`bench/run.py --check` + `tests/test_truth_shape.py`）。
