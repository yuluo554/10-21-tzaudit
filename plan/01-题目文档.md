## 一、介绍

### 1.1 问题：时区数据升级是一次**数据变更**，不是一次库升级

`tzdata` 不是一个季度更新一次的"字典"，它是一份**会改写历史**的数据库。IANA 发布说明里明确写着往回改的句子（✅ 原文，来自实际下载的发布包 `NEWS`）：

- **2026e**："In 1925 Ireland fell back on 09-20 not 10-04"
- **2026d**："Iran's 1979-05-26 spring forward was at 00:00, not 24:00"

也就是说：升级 tzdata **不会让程序报错**，它会安静地让三个月前的日志换一个 UTC 解释，让一张排班表的墙钟落到一个根本不存在的时刻。所有下游（调度系统、审计日志、账单、合规留存）都在同一刻被重写，而**没有任何测试会失败**。

更麻烦的是，**同一份 `tzdata` 源码可以编出两种语义不同的二进制**：`slim` 构建把远期规则压缩进 POSIX TZ 尾巴，`fat` 构建把规则展开成显式转换表。只比较转换表数量的工具，会在这两种构建之间**报"没有变化"**，而实际行为完全不同（见 §1.5）。

### 1.6 技术坑（**代理踩过并已修正**，必须原样进入实现，否则结论会错）

1. **POSIX TZ 偏移是"西为正"**。`EST5` 表示 UTC−5，`MST7` 表示 UTC−7。按"东为正"直读会把整块时区符号翻转，且错得很"像对的"（因为对称时区看不出来）。
2. **规则时间 `M3.2.0/2` 里的 `/2` 是**墙钟秒**，不能当偏移去减**。转换时刻 = 本地墙钟时间点，不是 UTC 秒；先按规则求本地那天的那一刻，再做一次"本地→UTC"的解析。
3. **`fold=0 ≠ fold=1` 在 gap 里也成立**。单看"两个 fold 的 offset 不同"就把该时刻判成 overlap，会在 gap 上**误报**（Vancouver 实测踩中：2026 年该 zone 已无 DST，旧代码仍报重叠）。因此：
   - **不存在（GAP）⟺ `roundtrip(local) != local`**；
   - **二义（OVERLAP）⟺ `roundtrip(local) == local` 且 fold 两值 offset 不同**。
   两套判据必须同时存在，缺一会双向误判。
4. **slim/fat 两种构建都要覆盖**：slim 把远期规则塞进 POSIX tail，fat 展开成显式表。**只读转换表**会得到"没有变化"的结论（Vancouver 就是 0 迁移数但语义全变）。

## 二、任务要求

首期 **5 个模块**，每个模块写清 **输入 / 输出 / 确定性纪律 / 验收**。所有模块共享 `data/README.md` §四的**数值口径**（gap/overlap 双判据、POSIX tail 解析规则、四类变更定义、退出码语义），**不得在代码或文案中另立第二套口径**。

### 模块 M1 — 双引擎时区解析器（`tzif` + POSIX tail 合并为统一时间线）

- **输入**：一棵 zoneinfo 树（`--zoneinfo <dir>`）或一个 tzdata 包解包目录；单个 zone 名（如 `America/Vancouver`）。
- **输出**：该 zone 的**统一时间线**——把 TZif 二进制转换表与 POSIX tail 规则合并成一条有序的"本地墙钟 ↔ UTC"映射，含：每个转换点的 UTC 时刻、前/后 offset、缩写、DST 标志，以及 tail 规则展开后的远期转换。
- **引擎**：
  1. **TZif 解析**：支持 v1 / v2 / v3 / v4 头部与 32/64 位两段数据，`slim`（仅一段 + tail）与 `fat`（显式表）两种构建；负 DST（Europe/Dublin 的冬季 `IST` 反而是"夏令"语义）、30 分钟偏移（Australia/Lord_Howe 的 `+10:30`/`+11:00`）、非整点（Pacific/Chatham 的 `+12:45`）必须原样保留。
  2. **POSIX tail 解析**：`std offset [dst [offset] [,start[/time],end[/time]]]`，支持 `Jn` / `n` / `Mm.w.d` 三种规则形式与 `/time` 后缀；**偏移按西为正**；`/time` 是**墙钟秒**（§1.6 坑 1、2）。
  3. **合并**：转换表覆盖的时间段用表，表外（或 slim 只有 tail 时）用 tail 规则展开；冲突时以"更晚的显式转换点"为界，并记录判定依据（`source: table|tail`）。
  4. **本地→UTC 反解**：给定本地墙钟时刻，返回**候选 UTC 列表 + 存在性**（这是 M2 的地基，也是竞品缺失的那一步）。
- **确定性纪律**：不读系统时区（忽略 `TZ` 环境变量）、不读 `locale`、不依赖文件系统遍历顺序（zone 按字节序排序）；同一输入双跑输出逐字节一致；输出不含主机名、绝对路径、生成时刻以外的任何环境信息。
- **验收**：**全量 zone 零解析错误**（以本地树实际 zone 数为分母，数字以末态回填）；**与独立参照实现（PEP 495 语义，`roundtrip` 定义见 §四）对拍一致**；`slim` 与 `fat` 两种构建对同一版本给出**语义等价**的时间线。

### 模块 M2 — 墙钟风险窗口表（`windows`）

- **输入**：`--zone <name> --year <YYYY>`；或 `--all --year <YYYY>`（全量 zone 批量）。
- **输出**（人类可读 + `--json`）：
  ```
  GAP      2026-03-08 02:00 → 03:00  (60min)  EST → EDT   America/New_York
  OVERLAP  2026-11-01 01:00 → 02:00  (60min)  EDT → EST   America/New_York
  ```
  字段固定：`type`（GAP / OVERLAP）、`start_local`、`end_local`、`duration_min`、`offset_before`、`offset_after`、`zone`、`source`（table / tail）。
- **引擎**：按 M1 的时间线逐转换点求"本地墙钟侧的空洞/重叠"，**双判据同时使用**：
  - 不存在 ⟺ `roundtrip(local) != local`；
  - 二义 ⟺ `roundtrip(local) == local` 且 `offset(fold=0) != offset(fold=1)`。
  未通过双判据的时刻**一律不报**（宁可漏报候选，不容许把不存在的空洞塞进清单）。
- **确定性纪律**：窗口按 `start_local` 升序、同起点按 `type` 字典序；时长以整分钟输出（秒级残差单独字段，不四舍五入成 60 分钟）；`--all` 遍历顺序为 zone 字节序；同一 zone 同一年双跑逐字节一致。
- **验收**：America/New_York 2026 **两个窗口各一条、方向正确**；**Vancouver 2026 不误报**（该 zone 已无常规 DST，只靠 fold 差异判 overlap 会误报）；跨年边界（12/31 与 1/1）不丢窗口；`--all` 模式在本地树上跑完不抛异常。

### 模块 M3 — 版本差异分类（`diff`）

- **输入**：两棵 zoneinfo 树 `--old <dir> --new <dir>`；可选 `--window <开始年>-<结束年>`（默认覆盖全历史）与 `--zone` 过滤。
- **输出**：每个 zone 一条（或零条）分类记录 + 汇总，四类**互斥**：
  - `future_rule`：转换表之外的行为变化（远期规则、POSIX tail 变化）；
  - `history_reinterpreted`：**过去的**墙钟→UTC 解释被改写；
  - `abbreviation_only`：仅缩写/命名变化，offset 语义不变；
  - `alias_only`：仅 link/alias 集合变化（含"legacy 名字换成缩写"）。
  字段：`zone`、`class`、`window`、`before`/`after` 摘要、`evidence`（`table` / `tail` / `abbr` / `link`）、以及人可读的一行说明。
- **引擎**：逐 zone 分别解析两棵树的 TZif + tail，先按时间线对齐求差；**再**用 tail 语义做二次判定——**当转换表相同但 tail 不同，必须判 `future_rule`**（Vancouver 实测：迁移数都是 0，但 `PST8PDT,M3.2.0,M11.1.0` → `MST7` 是彻底的行为变更）。`alias_only` 不得用于吸收真实的规则变化。
- **确定性纪律**：分类顺序固定（`history_reinterpreted` → `future_rule` → `abbreviation_only` → `alias_only`，取第一条成立的）；zone 输出按字节序；`evidence` 必须指到具体来源（表 / tail / abbr / link），不允许"综合判断"这类不可复算的措辞。
- **验收**：以 2026a 与 2026e 为输入，**能复现"窗口内变化的 zone 清单"与"全历史不同的 zone 清单"**（名单以末态金标回填，数字本身不写进代码）；**Vancouver 必须落在 `future_rule`**；`abbreviation_only` 与 `history_reinterpreted` 各有至少一条真实样例 fixture；对同一对输入双跑输出逐字节一致。

### 模块 M4 — 本地时间清单审计（`audit`）

- **输入**：**本地时刻清单**（CSV：`id,local_time`）或一行一个时间戳的文本；可选 `--zone <name>`（清单不含 zone 时必填）、`--version <A>,<B>`（两个 tzdata 版本目录）、`--daily HH:MM`（等价于按天展开的最小清单）。
  **刻意不接受 cron 表达式**（见 §六），只接受"本地时刻清单"与 `--daily`。
- **输出**：每条输入的判定：
  - `GAP`：该本地时刻在目标版本中**不存在**（附"上游数据本身有错，或用了 fold/normalize 掩盖"的说明与最近的合法区间）；
  - `OVERLAP`：该本地时刻**出现两次**（附两个 UTF 候选，标注调度可能跑两次）；
  - `VERSION_CHANGED`：在 A、B 两个版本下 **UTC 解释不同**（附两个 UTC 值）；
  - `OK`：唯一且两版本一致。
  汇总：各类计数 + **"同一 UTC 时刻在两个版本下的两个墙钟"**对照（Cal.com 场景的复现口径）。
- **引擎**：复用 M1 的反解 + M2 的双判据；版本差异复用 M3 的时间线对齐，但**只对被输入时刻求值**（不做全量 diff）。
- **确定性纪律**：输入行序保持输出行序（不做重排）；同一时刻的多个候选按 UTC 升序；CSV 解析失败的行**不静默跳过**，进入 `INVALID` 并在汇总里计数；不写绝对路径、不写主机名。
- **验收**：Cal.com 的 BC 场景可复现——**"同一 UTC 时刻，在两个版本下对应两个不同墙钟"**（构造数据，见 `data/README.md` 合成纪律）；gap / overlap / version_changed / ok 四类各至少一条用例；`--daily` 与等价清单输出一致。

### 模块 M5 — 报告与 CI 门禁（`report` / 退出码）

- **输入**：M2 / M3 / M4 的任意结果（`--json` 中间产物或直接串跑）。
- **输出**：**Markdown + JSON 双格式**；报告头**固定**写三项：**数据版本 / 生成时间 / 覆盖 zone 数**（缺一项即视为报告不合规）。
- **门禁**：`--fail-on gap|overlap|history`（可组合，逗号分隔）；命中即以 §四定义的退出码退出；未命中为 0。
- **确定性纪律**：JSON 键序固定；Markdown 表格列序固定；除报告头的"生成时间"外**不含任何时间戳**（保证其余部分可逐字节比对）；`--fail-on` 的判定只看结果集，不看人读文本。
- **验收**：干净数据集退出 0；注入 gap 命中 `--fail-on gap`；注入历史变更命中 `--fail-on history`；报告头三项齐全可被脚本断言；同一结果集生成的 JSON 双跑一致（忽略 `generated_at`）。

### 扩展项（明确列二期，不进首期判定路径）

- **多版本时间线对比**（A→B→C→D）：首期只做两版本对。
- **`right` / 闰秒模式**：**明确非主线**。依据：`tzdata/leap-seconds.list` 最后一条闰秒为 2017-01-01（Δ=37s）、文件到期 2027-06-28；而 POSIX 时间本身忽略闰秒，2026a 的 `NEWS` 已默认不再安装 `right` 文件。首期只解析、不建模、不比较。

## 六、边界与非目标

- **不做 cron 解析器**（明确避开）：`scheduler-mcp` 59★、`temporal-cortex` 13★，以及 crontab.guru 已经占住"cron 表达式解释"的用户心智。`audit` **只接受本地时刻清单或 `--daily HH:MM`**，不接受 cron 表达式；`--daily` 只展开成时刻，不解释"每月第几个周几"这类语义。
- **不做时区转换 / 世界时钟**（不做 `tz` 转换 CLI）：检索同类"时区转换"为红海（28 条结果），且属消费级功能，与审计无关。
- **不做纯 `zdump` 包装**：必须跨版本 + 墙钟窗口 + 分类；只转储单 zone 没有独立价值。
- **不做闰秒 / TAI 主线**：`hifitime` 552★、`zeit` 243★ 已覆盖，POSIX 时间本身忽略闰秒；首期只解析 `leap-seconds.list`、不建模、不比较。
- **不做日历规则 / 节假日**：`vacanza/holidays` 1958★ 已占位；ISO 周是标准库一行。
- **不做 GUI / 桌面 / exe 形态**：唯一形态是 CLI（输出 Markdown + JSON），供 CI 与终端消费。
- **隐私红线**：**纯本地、零网络**。不下载 tzdata、不上传清单、不写遥测；报告不写绝对路径、不写主机名、不写用户名。
- **数据纪律**：不内置"最新时区数据"、不硬编码任何实测数字（§1.5 的快照只作可行性证据）；版本包由用户提供，`--zoneinfo` / `--version` 指向本地目录。
- **结论纪律**：`diff` 的分类是"在给定两棵树与给定判定顺序下的结论"，不是"事实真相"；报告必须同时输出判定依据（`evidence`）与该口径。
- **品牌隔离**：本系列其他项目不得在文档、代码、提交信息中被提及。
- **首期范围限定**：两版本对（不做 A→B→C 链）、`--fail-on` 三选（`gap` / `overlap` / `history`）、单 zoneinfo 树解析（不做跨机采集）。
