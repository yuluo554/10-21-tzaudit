## 一、CLI 契约

```text
tzaudit [--version] <subcommand> [options]
  windows  --zone <name> --year <YYYY> [--json]
           --all --year <YYYY> [--json]
  diff     --old <dir> --new <dir> [--window <Y1>-<Y2>] [--zone <name>] [--json]
  audit    --times <file> (--zone <name> | --version <A>,<B>) [--json]
           --daily HH:MM --zone <name> [--version <A>,<B>] [--json]
  report   (--from <json> | 串跑子命令) [--format md|json] [--fail-on gap,overlap,history]
  version  --zoneinfo <dir> [--zone <name>] [--json]      # 树/版本自检（骨架期已有）
```

**全局规则**

- 未知子命令 / 缺必填 / 互斥参数 → 退出码 **2**（`argparse` 的 `SystemExit(2)` 在 `main()` 统一捕获，
  不向调用方抛栈）。
- 帮助文本为中文，术语保留英文键名（`GAP` / `OVERLAP` / `future_rule`），保证 `--json` 键与文档一致。
- `--json` 输出到 stdout；诊断/警告到 stderr；**stdout 只含结果**（可管道给 `jq`）。

## 二、`tzif.py` — TZif v1–v4 解析 `[M2]`

**输入**：`bytes`（整个 TZif 文件）。

**输出**：

```text
TzifData(
  version: "1"|"2"|"3"|"4",
  transitions: [(utc:int, offset_sec:int, is_dst:bool, abbr:str)],   # 升序
  initial: (offset_sec, is_dst, abbr),                               # 首个转换点之前
  footer: str|None,                                                  # POSIX TZ 串
  is_slim: bool,                                                     # footer 存在且表短
  raw_counts: {v1:int, v2:int},
)
```

**解析顺序**

1. 魔数 `TZif` → 版本字节（`\0` = v1，`2`/`3`/`4`）。
2. v1 头 44 字节：`isutcnt / isstdcnt / leapcnt / timecnt / typecnt / charcnt`。
3. 若版本 ≥ 2：跳过 v1 数据块，读第二头 + 64 位数据块，取**第二块**为准；`raw_counts.v1` 保留用于断言
   （"v2 文件里 v1 块必须存在且可解析"是格式要求，但语义以 v2 块为准）。
4. `timecnt` 个 `transition_time` → 对应 `type_index` → `(utcoffset, isdst, abbrind)` → `abbr` 从字符串表截取。
5. footer：两段数据块之后 `\n<posix tz>\n`；空串表示无 tail。
6. `is_slim` 判定：`footer 非空 且 表内转换点数 < 阈值`（阈值只在 `data/README.md` §4.2 之外的一个
   实现常数 `SLIM_MAX_TRANSITIONS = 2`，标注为"启发式，仅用于输出说明，不参与判定"）。

**必须原样保留的三种形态（题面 §1.6 / §二 M1）**

| 形态 | 断言 |
|---|---|
| 负 DST（Europe/Dublin 冬季 `IST` 是 DST=1） | `is_dst` 从字节原样取，不按"冬季=标准时"推断 |
| 30 分钟偏移（Lord_Howe `+10:30`） | `offset_sec = 37800`，不得取整到小时 |
| 非整点（Chatham `+12:45`） | `offset_sec = 45900` |

**失败路径**：魔数不符 / 长度不足 / `typecnt=0` / `abbrind` 越界 → `TzifParseError`（退出码 3，带
`zone` 与字节偏移）。**不返回部分结果**——损坏即报错，不"尽力解析"。

**测试点**（`tests/test_tzif.py`）

1. 用 `data/fixtures/tzif/` 的合成字节覆盖 v1/v2/v3/v4 四版本（`gen.py` 生成，含 64 位负时间）。
2. 三种特殊形态各一条（Dublin / Lord_Howe / Chatham），断言 `offset_sec` 与 `is_dst` 原样。
3. 截断字节（每个字段边界各切一刀）→ 必须 `TzifParseError`，不得 `IndexError`/`struct.error` 逃逸。
4. 全量树零解析错误（`bench` 侧，分母末态回填）。

## 三、`posix_tz.py` — POSIX TZ 解析与展开 `[M2]`

**输入**：`"EST5EDT,M3.2.0/2,M11.1.0/2"` 这类串。

**输出**：

```text
PosixTz(
  std: (offset_sec:int, abbr:str),
  dst: (offset_sec:int, abbr:str)|None,
  start: Rule|None, end: Rule|None,
  raw: str,
)
Rule(kind: "J"|"N"|"M", ...)   # Jn / n / Mm.w.d + time_sec
```

**解析规则**（逐条对应 `data/README.md` §4.2）

- 缩写：`<+1245>` 形式或 3+ 字母；**先尝试尖括号形式**，避免 `<` 被当普通字符。
- 偏移：`[+-]hh[:mm[:ss]]`，**西为正** → `offset_sec = -(sign*h*3600 + ...)`。
  单测反例：`EST5` 必须得 `-18000`；`MST7` 得 `-25200`；`<+1245>-12:45` 得 `+45900`。
- DST 偏移缺省 = `std_offset + 3600`（东向快 1 小时）。
- `start/end`：`J<n>`（1–365，跳过 2/29）、`<n>`（0–365，含 2/29）、`M<m>.<w>.<d>`（w=5 表示最后一个）。
- `/time`：**墙钟秒**，可负、可 ≥ 24h；解析为 `time_sec` 后由 `timeline` 在"本地那天的那一刻"使用，
  **解析层不做任何偏移加减**（PITFALL-WALLSEC）。

**失败路径**：未知形式 → `PosixTzError`（退出码 3）。**不做宽容解析**（不"猜一个近似规则"）。

**测试点**（`tests/test_posix_tz.py`）

1. `EST5` / `EST5EDT` / `EST5EDT,M3.2.0,M11.1.0` / `MST7` / `<-03>3<-02>,M3.5.0/-2,M10.5.0/-1` / `<+1245>-12:45<+1345>,M9.5.0/2:45,M4.1.0/3:45`。
2. 三类规则形式各一条边界：`J60`（3/1，闰年也 3/1）、`59`（闰年 2/29）、`M3.5.0`（最后一个周日）。
3. `/time` 为墙钟秒：`M3.2.0/2` 在 `America/New_York` 上展开得到的 UTC 必须是 `07:00Z`（EST 时），
   而不是 `02:00Z`（后者是把 `/2` 当偏移的错误形态）。
4. `MST7`（无 DST）→ `dst is None`，`timeline` 表外不产生任何 DST 转换。

## 四、`timeline.py` — 双引擎合并与本地反解 `[M2]`

### 4.1 构造

```python
load_timeline(zone, store) -> Timeline     # 读文件 + 解析 + 合并，无全局状态
```

- 读 `store.path_for(zone)` → `tzif.parse` → `posix_tz.parse(footer)`。
- 表段：每个转换点 `[t_i, t_{i+1})` 一个 `Segment(source="table")`。
- 表尾之后：若 `tail` 存在，从 `max(table_end, window_start)` 起按 tail 规则**逐年展开**
  （展开上限 = 请求窗口末端 + 1 年，不是"永远"——避免无限循环）；`source="tail"`。
- **展开起点可早于 1970**（slim 树的历史区间也可能靠 tail）。

### 4.2 反解

```python
resolve_local(local: int, tl: Timeline) -> list[Resolution]
to_local(utc: int, tl: Timeline) -> int
roundtrip(local: int, tl: Timeline) -> list[int]
```

算法（O(log n)）：

1. 用 `local - max_offset` / `local - min_offset` 得 UTC 搜索区间（`max/min` 取自所有 segment + tail）。
2. 在该区间内取每个候选 offset `o`：`utc = local - o`；若 `to_local(utc) == local` 则收为候选。
3. 候选去重（同 utc 只留一条），按 utc 升序；`fold` = 候选序号（0/1）。

- 0 个 → GAP；2 个 → OVERLAP；1 个 → OK。**`fold` 不参与存在性判断**（PITFALL-FOLD-GAP）。

### 4.3 测试点

1. **双向对拍**：`roundtrip(resolve_local(l)) == l` 对 fixture 全量逐行成立（M1 门槛）。
2. **独立参照实现**：`tests/reference.py` 用 `datetime` + 手工构造的 `offset` 表实现同语义，
   与生产实现逐条对拍（**不共享代码**，AST 守门禁止生产模块 import 它）。
3. Vancouver 2026：`resolve_local(2026-07-01 12:00)` 只有 1 个候选（无 DST 后不得给 2 个）。
4. Dublin 1916（负 DST 区间）：`is_dst` 与 offset 同表内一致。
5. slim vs fat 同版本：对同一 zone 生成的时间线在**重叠时间范围**内逐转换点语义等价
   （`tests/test_slim_fat.py`；跳过"仅一侧存在"的转换点并逐条打印）。
   **Q1 定案（2026-10-21）**：fat 不参与主金标，只在 M2 fixture 里从源码包自建；
   比对口径是"重叠区间语义等价"，**不要求版本号相同**。

## 五、`windows.py` — 墙钟风险窗口 `[M3]`

```python
scan_year(zone, year, tl) -> list[Window]
Window(type, start_local, end_local, duration_min, residual_sec,
       offset_before, offset_after, zone, source)
```

**算法**

1. 取该年覆盖的转换点（表 + tail 展开）`t_i`。
2. 对每个转换点：`before = offset(t_i - 1)`, `after = offset(t_i)`。
   - `after > before` → 候选 GAP：`[t_i + before, t_i + after)` 的本地墙钟段（长度 = `after - before`）。
   - `after < before` → 候选 OVERLAP：`[t_i + after, t_i + before)`。
3. **逐候选复核双判据**：对候选段内取**首/中/末三点**（以及整分钟网格，若长度 < 3 分钟则逐秒）
   跑 `resolve_local`：GAP 段必须 `len==0`；OVERLAP 段必须 `len==2` 且两 offset 不同。
   任一不满足 → **丢弃该候选**（宁漏不误报，题面 §二 M2）。
4. 输出按 `start_local` 升序、同起点 `type` 字典序（`GAP` < `OVERLAP`）。
5. `duration_min = (end - start) // 60`；`residual_sec = (end - start) % 60`（不并进分钟）。

**`--all` 模式**：遍历 `store.zones()`（字节序），单 zone 异常 → 该 zone 记 `error` 进 `summary.errors`，
**不中断整批**；退出码仍按结果集（有 error 时退 3）。

**测试点**（`tests/test_windows.py`）

1. `America/New_York 2026` → 恰好两条：GAP `02:00→03:00`、OVERLAP `01:00→02:00`，方向正确，`source=table`。
2. **Vancouver 2026 → 零条**（反例：只按 fold 判 overlap 的实现会在这里报一条）。
3. 跨年边界：`Australia/Lord_Howe 2026`（30 分钟 DST）→ 两条，`duration_min=30`；
   `Pacific/Chatham 2026` → 两条，偏移含 45 分钟。
4. `--all --year 2026` 在 fixture 小树上跑完不抛异常，`summary.zones` 与扫描数一致。
5. 同一 zone 双跑逐字节一致（忽略 `generated_at`）。

## 六、`diff.py` — 版本差异分类 `[M4]`

```python
diff_trees(old_store, new_store, window=None, zone=None) -> DiffResult
Change(zone, class_, window, before, after, evidence, note)
```

**判定顺序（固定，取第一条成立者）**

1. `history_reinterpreted`：在 `window`（默认 = 两树共有历史的交集）内存在**任一** UTC 时刻，
   两树的 `to_local` 不同 → 成立。`evidence` = 差异来自表段还是 tail 段。
2. `future_rule`：`window` 之后（或 tail 生效区）存在语义差异——**先比 tail 的规范化结构**
   （`std/dst/start/end` 四元组），再比表尾之后的展开；**表相同但 tail 不同必须落这里**
   （Vancouver 2026.1→2026.5：`PST8PDT,M3.2.0,M11.1.0` → `MST7`）。
3. `abbreviation_only`：所有转换点 `utc/offset` 相同，仅 `abbr` 不同 → `evidence=abbr`。
4. `alias_only`：zone 在 link 集合中新增/消失，且**无任何 offset/规则差异** → `evidence=link`。

- `alias_only` **不得**吸收规则变化：进入第 4 步前必须已排除 1–3（结构上由顺序保证）。
- `before`/`after` 是**摘要**（如 `"tail=PST8PDT,M3.2.0,M11.1.0"` / `"transitions=0"`），
  不是全文；全文进 `--json` 的 `detail`（可选，默认不带）。

**link 识别**：slim 树里 link 常是**同内容的副本文件**而非符号链接（Windows 解包会丢符号链接）。
判据 = `st_size` 相同 + 内容 sha256 相同 → 视为 link 候选，并记录 `evidence=link`；
**不能用"文件名像 link"推断**。

**测试点**（`tests/test_diff.py`）

1. Vancouver（构造 slim fixture）→ `future_rule` + `evidence=tail`；**断言 `class` 不是 `alias_only`**。
2. Dublin 1925 / Tehran 1979（真实数据 fixture）→ `history_reinterpreted`。
3. 仅缩写变化（构造）→ `abbreviation_only`，且 `history_reinterpreted` 与 `future_rule` 均不成立。
4. 四类互斥：同一 zone 只输出一条；构造"同时有 abbr 与 tail 差异"的 fixture → 必须落 `future_rule`。
5. 判定顺序变异：把顺序改成 `future_rule` 优先 → 第 2 条测试必须红（变异验证写进测试注释）。

## 七、`audit.py` — 本地时间清单审计 `[M5]`

```python
audit_rows(rows, zone, versions=(A,B)|None) -> AuditResult
Row(id, local, status, utc_candidates, note, invalid_reason)
```

- 输入：CSV `id,local_time`（`local_time` 接受 `YYYY-MM-DD HH:MM[:SS]`）；或一行一个时间戳（无 id 时
  自动 `line-001`）。`--daily HH:MM` → 展开为 `year` 范围内每天一条（默认年 = 清单/参数指定，
  缺省报退出码 2，**不默认当前年**——不读时钟）。
- 判定顺序：`INVALID`（解析失败）→ `GAP` → `OVERLAP` → `VERSION_CHANGED` → `OK`。
  `VERSION_CHANGED` 只在 `--version` 给定时可能成立（两版本 `resolve_local` 的 UTC 集合不同）。
- **行序保持输入序**；同一时刻多候选按 UTC 升序。
- `INVALID` 行**不静默跳过**：进结果 + 计数；有 `INVALID` 时整体退出码 4（`data/README` §4.4）。
- `--version A,B` 的 A/B 是**目录路径**（`--version data/tzdb/2026a,data/tzdb/2026e`），
  不是版本号字符串（**Q4 定案 2026-10-21**：工具不内置任何版本，与"零网络、用户提供数据"一致）——
  路径必须存在且带 `provenance.json`，否则退 3。

**测试点**（`tests/test_audit.py`）

1. 四类各一条：`GAP`（`2026-03-08 02:30` NY）、`OVERLAP`（`2026-11-01 01:30` NY）、
   `VERSION_CHANGED`（BC 场景）、`OK`。
2. BC 场景：同一 UTC 在 2026a / 2026b 下两个不同墙钟（构造 fixture，`data/README` §三 合成纪律）。
3. `--daily 02:30` 与等价清单输出逐字节一致（除 `id` 前缀）。
4. CSV 坏行（缺列、时间非法、空行）→ `INVALID` + 计数 + 退出码 4，且**其余行照常判定**。
5. 输出行序 == 输入行序（打乱输入后断言）。

## 八、`report.py` — 报告与门禁 `[M5]`

```python
build_report(results, data_version, zones_covered, generated_at) -> (md:str, doc:dict)
gate_exit_code(doc, fail_on: set[str]) -> int
```

- 报告头三字段：`data_version` / `zones_covered` / `generated_at`（`data/README` §4.5）。
  缺任一 → `ReportIncomplete`（退出码 3）。
- `--fail-on` 只看**结果集**：`gap` → 存在 `type=GAP`；`overlap` → 存在 `type=OVERLAP`；
  `history` → 存在 `class=history_reinterpreted`。命中 → 1。
- Markdown 表格列序固定；**除 `generated_at` 外零时间戳**；JSON 键序 `sort_keys=True`。
- `--format md|json`；未知格式 → 退出码 2（显式拒绝，不回落）。

**测试点**（`tests/test_report.py`）

1. 干净结果 → 退出 0；注入 gap → `--fail-on gap` 退 1；注入 history → `--fail-on history` 退 1。
2. 报告头缺字段 → 退 3（构造直接调 `build_report`，不经 CLI）。
3. 双跑 JSON 一致（`generated_at` 用 `SOURCE_DATE_EPOCH` 冻结后**逐字节**一致）。
4. Markdown 里不含 `C:\` / `/home/` / 主机名（正则断言）。

## 九、`cli.py` — 分派与退出码 `[骨架+M2–M5]`

- `main(argv=None) -> int`：**唯一**读 `sys.argv` 的地方；测试一律传 `argv`。
- 异常映射（单点，`errors.py` 定义类型）：

| 异常 | 退出码 |
|---|---|
| `UsageError` / `argparse` 的 `SystemExit(2)` | 2 |
| `EnvironmentError`（路径不存在 / 缺 provenance / TZif 损坏） | 3 |
| `InvalidInput`（清单坏行超阈值） | 4 |
| `NotImplementedYet` | 5（骨架期；随模块落地**整项退役**） |
| 其他未捕获异常 | 1（并打印 `internal error: <type>` 到 stderr，不吞栈到 stdout） |

- `--version` 输出 `tzaudit <__version__>`。

## 十、`bench/run.py` — 金标复算 `[M1 起]`

```bash
py -3.12 bench/run.py --check          # 复算全部金标，逐项比对
py -3.12 bench/run.py --check --suite windows
py -3.12 bench/run.py --regen          # 重新生成金标（需真数据树，仅在数据升级时用）
```

- `--check` 的**分母**打印在结果行（"复算 N 项，M 不一致"），N=0 单独报 FAIL（判据空跑）。
- 金标文件 `data/tzdb/<ver>/expect.json` 只存**输入 + 期望**；不含 `observed_*`。
- `--regen` 在临时目录生成后与入仓件逐字节比对（`--check` 的核心断言），**不是**"重新写一遍就当通过"。
