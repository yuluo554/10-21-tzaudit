## 五、发布流程（M6，按真实动作序列）

```text
1. 定版提交：版本号三处一致 + 样例/金标重生成 + 状态回写 + HANDOFF-M6
2. 本地全量：pytest（3.8/3.12）+ 布局门 + 脱敏门 + bench --check
3. 干净环境：git archive 导出 → 解包 → 新 venv → 按 README 逐条敲（含前置条件）
4. 断网验证：socket 打桩 + netstat 旁证
5. 建仓：gh repo create yuluo554/10-21-tzaudit --public
6. 首推 main → 观察 CI（红则修，**首跑失败照录**）
7. 打 tag：git tag -a v0.1.0 -m ... → push tag → 观察 tag run
8. 附件：git archive --format=tar --prefix=10-21-tzaudit-0.1.0/ v0.1.0 | gzip -9n > ...tar.gz
        + SHA256SUMS → gh release create v0.1.0 <附件> --notes-file
9. 本体复核：gh release download → sha256sum -c → 解包树与 git archive 树共有文件逐字节比对
10. 留档：plan/RELEASE-M6.md §二 追加（字面值只写在这里，不写进 tag 树）
```

**不可写进 tag 树的值**：附件 sha256、tag 对象 OID、tag 指向的 commit、本次 push 的 run 计数
（自指：写一次失效一次）。`plan/RELEASE-M6.md` 在 tag 树内的两栏只写**结构 + 复验方法**。

## 六、验收口径（每个里程碑都用同一条）

- **门要能跑红**：新增判据必须配一条变异（改坏被测行为 → 门红 → 还原 → 绿）。
- **"没红"先分三问**：变异真改到字节了吗？改的是数据还是措辞？判据是否自我参照/或关系/写死顺序？
- **未执行不写"已完成"**：CI、跨平台、干净环境，未做就写"未验证 + 何时验"。
